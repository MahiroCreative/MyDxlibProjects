## 3. 自動検証

```
cd extension
npm install
node esbuild.js && npx tsc --noEmit -p ./
node test/runTest.js %TEMP%\dxt "<SDK フォルダの絶対パス>"
```

- **作業フォルダは短いパスにする(例: `%TEMP%\dxt`)。** ビルド用 bat は `<作業フォルダ>\user-data\User\globalStorage\mahirocreative.dxlib-devenv\build\` にでき、長いと 260 文字の上限を超える(Claude Code のスクラッチパッドを使ったら Release の bat が 261 文字になって NG になった)。生徒の PC では問題にならない。
- 段階 1〜8 が順に走る。所要は約 25 分。段階 6〜8 だけなら末尾に `--phase6-only` / `--phase7-only` / `--phase8-only`(全段階を 1 回通した作業フォルダで)。段階 8 は初回だけ C/C++ Extension Pack をダウンロードする。
- 出力の `[phaseN] OK/NG` を数える。1 件でも NG があると、その段階で止まる。
- スクリーンショットは `<作業フォルダ>/screenshots/`。合否ではなく、人(Claude)が画像を見て判断する。

**踏みやすい落とし穴**

- Claude Code など VSCode の拡張の中から実行すると `ELECTRON_RUN_AS_NODE=1` が引き継がれ、Code.exe が Node として動いて失敗する。`runTest.js` が消している。
- VSCode 本体が自動更新中だと、検証用の VSCode も起動できない。**ユーザーの VSCode を勝手に閉じない**。
- `@vscode/test-electron` の `runTests` は必ず `--disable-workspace-trust` を付けるので制限モードにならない。また開発中の拡張(`extensionDevelopmentPath`)は信頼の制限を受けない。制限モードの検証は、VSIX をインストールし、検証コードは中身の無い検証用の拡張(`trust-harness`)として読み込む(段階 7)。
- 検証用に起動した VSCode では「おすすめの拡張」の通知が出ない。おすすめを止める設定(extensions.json)が効くかは手動でしか確かめられない。
- C/C++ 拡張は **C++ のファイルがエディタで開かれるまで設定プロバイダーに問い合わせてこない**。補完まわりの検証は `main.cpp` を開いてから待つ。「切り替え後の最初の問い合わせ」ではなく「期待する設定を含む問い合わせ」を待つ(直前のファイルオープンに反応した古い問い合わせを拾って NG になったことがある)。
- 確認ダイアログは `showErrorMessage` などの差し替えで自動応答させる。差し替えは必ず `finally` で戻す。`vscode.openFolder` も差し替えで横取りして記録する(実際に開くと検証中の窓が置き換わる)。
- C/C++ 拡張の「定義を作成」は編集を未保存のまま残す。片づけは「保存 → エディタを閉じる → 削除」。
- 整形器(C/C++ 拡張も DxLib 拡張の HLSL 整形器も)は、直す所が無いと空の配列ではなく `undefined` を返し、「応答しない」と区別できない。「整形で変わらない」を確かめるときは、必ず直される行(探り)を末尾に足して比べる(段階 2)。また、VSCode が一度開いたファイルをディスク上で書き換えると、古い中身のまま整形されることがある。探り付きの写しは別名の新しいファイルに作る。
- VSCode はドライブ文字を小文字(`c:\`)で返すことがある。パスの比較は大文字小文字を無視する。
- ゲームが書き込み中の `Log.txt` は EBUSY で読めないことがある。読めるまで待つ。
- スクリーンショット(`test/screenshot.ps1`)は、対象の窓が見つからないと **ユーザーの画面を撮ってしまう** ことがある(2026-09-24 に 1 回。手元の一時フォルダに残っただけ)。

**クリック操作による確認(`test/ui/`、2026-09-24 夜に追加)**

手動確認の代わりに、別プロファイルの VSCode に本物のマウス・キー入力を送り、スクリーンショットを Claude が見て判断する。合否の自動判定は無い。**実行中はユーザーにマウスとキーボードに触らないよう頼む。**

```
cd extension
npm run release
node test/ui/setup.js %TEMP%\dxui "<SDK フォルダ>" "<cpptools の VSIX>"
node test/ui/launch.js %TEMP%\dxui [開くフォルダ]
powershell -NoProfile -ExecutionPolicy Bypass -File test/ui/ui.ps1 -UserDataDir %TEMP%\dxui\user-data -Action click -X 49 -Y 414 -Out %TEMP%\dxui\shots\01.png -WaitMs 1500
```

- `setup.js` はプロファイルを作り直し、`release/` の VSIX と C/C++ 拡張を入れる(言語パック・HLSL Tools は拡張パックで入る)。
- `ui.ps1` の動作は shot / click / dclick / rclick / hover / keys(SendKeys の書き方。例 `^%d`)/ type(クリップボード経由で貼り付け)。座標は窓の左上からの物理ピクセルで、スクリーンショットと同じ。
- 検証用の窓は、コマンドラインの `--user-data-dir` で見つける。前面に出せなければ入力を送らずに止まる(ユーザーの窓に誤って入力しないため)。
- 前面に出すための ALT は、前面でないときだけ押す。VSCode では ALT でメニューバーに移り、後の入力が消える(フォームに入力できなかった原因)。
- 同じプロファイルの窓を 2 つ開くと見分けられない。別のフォルダを開くときは `Code.exe --user-data-dir ... --extensions-dir ... --reuse-window <フォルダ>` で同じ窓を置き換える。
- 終わったら、コマンドラインに `%TEMP%\dxui\user-data` を含む Code.exe だけを止める。

## 7. 進め方のルール(ユーザーとの取り決め)

- **モデルの最低ラインは Sonnet 5・中。Haiku は使わない。**
- **実機で動かして確かめる作業・実機で見つかった不具合の原因調査は Opus 5.5。** 切り替えが必要になったら、その場でユーザーに「次は ○○・△」と伝える(DESIGN.md 17.1)。
- 検証コードは「常に合格する」「分岐の片側しか通らない」「形だけ見る」「名前と中身が違う」になっていないかを疑う。**直したら、直す前のコードで NG になることも確かめる**(2026-09-24 は段階 6・7 でこれをやり、段階 7 の最初の形が検証になっていないことが分かった)。
- 仕様を変えるときは先に DESIGN.md を直す。
- コミット・push はユーザーが頼んだときだけ。
- **作業中は、この窓でも進捗を見せる(2026-09-24 ユーザー依頼)。** 長い作業(自動検証の全段階など)を裏で走らせて黙って返事を終えない。数分ごとに様子を見て「段階 2 に入った」「NG が出た」など短く書く。
- 手動確認の項目は、今の DxLib で実際に確かめられるものだけにする(「残り n 件」の反省)。

## 8. 決定事項の要約(詳細は DESIGN.md)

- 対象は生徒。UI はすべて日本語。コマンドパレットは使わせず、パネルのボタンとフォームで操作する。
- 配布は VSIX の直接インストール。**VSIX はダブルクリックさせず `install.bat` を使う**(18 章)。`install.bat` の CRLF は `scripts/release.js` がそろえる(`.gitattributes` には頼らない)。
- SDK は生徒が自分で置きパスを指定する。間違いでも保存して ✗。正しくない間はプロジェクトを作成できない。途中で場所を変えても「変更」で指し直せばよい(5 章)。
- ビルドは `cl.exe` 直叩き。ソースは BOM 付き UTF-8 + `/source-charset:.932 /execution-charset:.932`。ビルドエラーの赤線は拡張が管理する(6 章)。
- IntelliSense には UTF-8 に変換したヘッダーの写しを読ませる。ビルドは元の SDK(7 章)。
- 作成後の開き方: 空の窓ならその窓、使用中なら新しい窓。作成先の初期値は前回の作成先(8 章)。
- 制限モードでも DxLib パネルは出し、信頼の案内を表示する(1 章の表、17.4 章)。
- テンプレートは「フォルダ 1 つ = 1 テンプレート」(`template.json`)。同梱は「最小」のみ。
- シェーダーは Direct3D 11 モード。既定ターゲットは `vs_4_0` / `ps_4_0`。
- ライセンスは MIT(`extension/LICENSE`)。`00_DxLib_Make` は DxLib 作者のライセンスで MIT の対象外。
- ウォークスルーの画像は付けない。
- Direct3D 9 と 11 の違いの経緯: DxLib は D3D9 時代の使い方のまま D3D11 対応したので、「2D では自作の頂点シェーダーが無視される」「入力の並びを合わせないと壊れる(エラーも出ない)」。ユーザーは仕様として受け入れた。
