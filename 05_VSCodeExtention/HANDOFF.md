**踏みやすい落とし穴**

- Claude Code など VSCode の拡張の中から実行すると `ELECTRON_RUN_AS_NODE=1` が引き継がれ、Code.exe が Node として動いて失敗する。`runTest.js` が消している。
- VSCode 本体が自動更新中だと、検証用の VSCode も起動できない。**ユーザーの VSCode を勝手に閉じない**。
- **スクリーンショット(`test/screenshot.ps1`)**: Windows は裏のプログラムからの `SetForegroundWindow` を無視する。以前はそのまま撮って **ユーザーの画面を撮ってしまって** いた(2026-09-24・25 に計 3 回。手元の一時フォルダに残っただけ)。2026-09-25 に、ALT を一瞬押してから前面に出し(ui.ps1 と同じ方法)、**出せなければ撮らずに失敗する**ようにした。**撮る瞬間にユーザーが PC を操作していると前面に出せず、段階 3 のスクリーンショットが全部 NG になる**(2026-09-25 に 1 回。拡張の不具合ではない)。段階 3 の間はユーザーに触らないよう頼む。
- `@vscode/test-electron` の `runTests` は必ず `--disable-workspace-trust` を付けるので制限モードにならない。また開発中の拡張(`extensionDevelopmentPath`)は信頼の制限を受けない。制限モードの検証は、VSIX をインストールし、検証コードは中身の無い検証用の拡張(`trust-harness`)として読み込む(段階 7)。
- 検証用に起動した VSCode では「おすすめの拡張」の通知が出ない。おすすめを止める設定(extensions.json)が効くかは手動でしか確かめられない。
- **右クリックのメニューが出るかどうか(`when` の条件)は自動検証で読み取れない。** 段階 2 はコマンドをメニューと同じ引数で呼ぶだけ。メニューの出方はクリック操作で確かめる(2026-09-25 に確認済み。DESIGN.md 17 章の最後)。
- C/C++ 拡張は **C++ のファイルがエディタで開かれるまで設定プロバイダーに問い合わせてこない**。補完まわりの検証は `main.cpp` を開いてから待つ。「切り替え後の最初の問い合わせ」ではなく「期待する設定を含む問い合わせ」を待つ。
- 確認ダイアログは `showErrorMessage` などの差し替えで自動応答させる。差し替えは必ず `finally` で戻す。`vscode.openFolder` も差し替えで横取りして記録する(実際に開くと検証中の窓が置き換わる)。
- C/C++ 拡張の「定義を作成」は編集を未保存のまま残す。片づけは「保存 → エディタを閉じる → 削除」。
- 整形器は、直す所が無いと空の配列ではなく `undefined` を返し、「応答しない」と区別できない。「整形で変わらない」を確かめるときは、必ず直される行(探り)を末尾に足して比べる(段階 2)。VSCode が一度開いたファイルをディスク上で書き換えると、古い中身のまま整形されることがある。探り付きの写しは別名の新しいファイルに作る。
- VSCode はドライブ文字を小文字(`c:\`)で返すことがある。パスの比較は大文字小文字を無視する。
- ゲームが書き込み中の `Log.txt` は EBUSY で読めないことがある。読めるまで待つ。
- PowerShell のヒアストリング(`@"..."@`)に TypeScript のテンプレート文字列 `${...}` を書くと、PowerShell の変数として展開されて消える(2026-09-25 に 1 回。`dxlib.projectView.focus` が `.focus` になった)。書き換えたら必ず中身を読んで確かめる。

**クリック操作による確認(`test/ui/`)**

手動確認の代わりに、別プロファイルの VSCode に本物のマウス・キー入力を送り、スクリーンショットを Claude が見て判断する。合否の自動判定は無い。**実行中はユーザーにマウスとキーボードに触らないよう頼む。**

```
cd extension
npm run release
node test/ui/setup.js %TEMP%\dxui "<SDK フォルダ>" "<cpptools の VSIX>"
node test/ui/launch.js %TEMP%\dxui [開くフォルダ]
powershell -NoProfile -ExecutionPolicy Bypass -File test/ui/ui.ps1 -UserDataDir %TEMP%\dxui\user-data -Action click -X 49 -Y 414 -Out %TEMP%\dxui\shots\01.png -WaitMs 1500
```

- `setup.js` はプロファイルを作り直し、`release/` の VSIX と C/C++ 拡張を入れる(言語パック・HLSL Tools は拡張パックで入る)。cpptools の VSIX は、自動検証の作業フォルダの `cpptools.vsix`(段階 6 が作る)を使える。
- 開くプロジェクトは、自動検証の `%TEMP%\dxt\projects\TestGame` を `build`・`bin` を除いてコピーすると早い(`shaders` に `TestPS.hlsl`・`TestVS.hlsl` がある)。
- `ui.ps1` の動作は shot / click / dclick / rclick / hover / keys(`-Text` に SendKeys の書き方。例 `'{ESC}'`・`'^%d'`)/ type(クリップボード経由で貼り付け)。座標は窓の左上からの物理ピクセルで、スクリーンショットと同じ。
- 検証用の窓は、コマンドラインの `--user-data-dir` で見つける。前面に出せなければ入力を送らずに止まる。
- 前面に出すための ALT は、前面でないときだけ押す。VSCode では ALT でメニューバーに移り、後の入力が消える。
- `shot` は窓を前面に出さない。後ろにあると、その位置のユーザーの画面を撮ってしまう。先に `click` で前面に出す。**タイトルバーの中央は検索欄**なので避ける(x=700, y=12 は検索が開いた)。エクスプローラーのアイコン(x=33, y=57)をクリックするのが無難。
- ワークロード追加の確認: 環境変数 `DXLIB_TEST_SIMULATE_NO_WORKLOAD=1` を付けたシェルから `launch.js` で起動すると、パネルが「未インストール」と「ワークロードを追加」を出す(DESIGN.md 4 章)。UAC はユーザーに「はい」を押してもらう。ワークロードが入っていると **インストーラーは 4 秒ほどで終わる**ので、プロセスの監視では取り逃がしやすい。確かめるのは `%TEMP%\dd_installer_*.log`(`Parsed command line options` と `Exit Code: 0`)と、パネルの通知。
- 同じプロファイルの窓を 2 つ開くと見分けられない。別のフォルダを開くときは `Code.exe --user-data-dir ... --extensions-dir ... --reuse-window <フォルダ>`。
- 終わったら、コマンドラインに `%TEMP%\dxui\user-data` を含む Code.exe だけを止める。

## 8. 決定事項の要約(詳細は DESIGN.md)

- 対象は生徒。UI はすべて日本語。コマンドパレットは使わせず、パネル・エクスプローラーの欄のボタンとフォーム、右クリックで操作する。
- **DxLib パネル**は環境の状態・新規プロジェクト作成・現在のプロジェクト名だけ。**ビルド・実行・デバッグ実行・シェーダー・テンプレート保存は、エクスプローラーの「DxLib」欄と右クリック**。フォームは欄の中で開く(タブで開く形は試して戻した)(3.1 章)。
- 配布は VSIX の直接インストール。**VSIX はダブルクリックさせず `install.bat` を使う**(18 章)。`install.bat` の CRLF は `scripts/release.js` がそろえる(`.gitattributes` には頼らない)。
- SDK は生徒が自分で置きパスを指定する。間違いでも保存して ✗。正しくない間はプロジェクトを作成できない。途中で場所を変えても「変更」で指し直せばよい(5 章)。
- ビルドは `cl.exe` 直叩き。ソースは BOM 付き UTF-8 + `/source-charset:.932 /execution-charset:.932`。ビルドエラーの赤線は拡張が管理する(6 章)。
- IntelliSense には UTF-8 に変換したヘッダーの写しを読ませる。ビルドは元の SDK(7 章)。
- 作成後の開き方: 空の窓ならその窓、使用中なら新しい窓。作成先の初期値は前回の作成先(8 章)。
- 新しいシェーダーのファイル名は `<名前>_2DPS.hlsl` / `_3DPS` / `_3DVS`(9 章)。
- 制限モードでも DxLib パネルは出し、信頼の案内を表示する(エクスプローラーの欄は出さない)(17.4 章)。
- テンプレートは「フォルダ 1 つ = 1 テンプレート」(`template.json`)。同梱は「最小」のみ。
- シェーダーは Direct3D 11 モード。既定ターゲットは `vs_4_0` / `ps_4_0`。
- ライセンスは MIT(`extension/LICENSE`)。`00_DxLib_Make` は DxLib 作者のライセンスで MIT の対象外。
- ウォークスルーの画像は付けない。
- Direct3D 9 と 11 の違いの経緯: DxLib は D3D9 時代の使い方のまま D3D11 対応したので、「2D では自作の頂点シェーダーが無視される」「入力の並びを合わせないと壊れる(エラーも出ない)」。ユーザーは仕様として受け入れた。
